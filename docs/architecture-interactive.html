vizcrush sits between your data source and rendering library. Feed it raw Float64Array data from APIs, CSVs, or WebSockets. It returns optimized arrays ready for D3, Three.js, Plotly, or Canvas — any renderer works.
Backend auto-selection priority
1. WASM 2. JS fallback
Checks WebAssembly support and loads the compiled Rust module. Falls back to pure JS silently — no errors, guaranteed to work. Per-call override: auto | wasm | js.
WASM

JS fallback

LTTB downsampling pipeline
1M points → 1,920 points (screen width); timing varies by engine and hardware
LTTB MinMax M4 LTOB
O(n) single pass — divides data into buckets, keeps the point forming the largest triangle area with its neighbors. Visual fidelity preserved.
Binning algorithms
bin1d bin2d hexbin bin3d
2D binning aggregates points into density grids (e.g. 128x128) in a single pass on the WASM or JS backend. Ideal for heatmaps and density plots.
Spatial indexing
Quadtree kd-tree Octree kNN Frustum cull
Build: 500K 3D points → octree in ~200ms (one-time). Query: range/kNN in less than 1ms per frame. LOD reduces 500K → 60-80K rendered points for 60fps.

Build pipeline
Rust crates compile to WASM via wasm-bindgen. TypeScript packages build with tsc orchestrated by Turbo. Five WGSL compute shaders ship in the repo: bin2d's is wired as an opt-in path — measured slower than WASM (ADR 0004) — and the rest are unwired drafts. 158 Rust tests + 277 TypeScript tests + benchmark regression checks.
